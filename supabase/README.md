# Supabase — صيانة الخلفية

- functions/: مصدر وظائف Edge، لكل وظيفة مجلد مستقل. لا تنشر ملفات من docs/pending-edge.
- migrations/: سجل SQL مرتب بتوقيت UTC. لا تعيد كتابة ترحيل مطبق أو تجمعه مع ترحيلات تاريخية بغرض التنظيف.
- قاعدة الإنتاج هي المصدر الفعلي للبيانات. GitHub يحفظ المخطط والكود وليس نسخة احتياطية من البيانات.

## دورة التعديل
1. افحص الترحيلات المسجلة في المشروع الحقيقي وقارن أسماءها وإصداراتها مع GitHub.
2. اكتب ترحيلاً جديداً قابلاً للمراجعة. افحص RLS، grants، صلاحيات الوظائف وتكامل المحاسبة والمخزون.
3. اختبر على بيئة معزولة، وخذ نسخة احتياطية خارج Git. لا تستخدم بيانات عملاء حقيقية في الاختبارات.
4. طبق الترحيل بعد اجتياز الاختبار وسجل رقم النسخة. انشر Edge فقط إذا تغير مصدرها.
5. قارن مصدر كل Edge منشورة مع الملف في GitHub. افحص المستشار الأمني واختبر الطلبات بصلاحياتها الفعلية.
6. حدّث ملاحظات الإصدار وحدد ما اختبر فعلياً وما بقي.

لا تستخدم npm run verify لتطبيق SQL أو نشر الوظائف؛ الأمر مخصص للفحوص المحلية فقط. الاختبار الذي ينتهي بـ ROLLBACK ليس اختبار استعادة نسخة احتياطية.

لحدود النسخة الحالية راجع [سجل الإصدارات](../docs/releases/README.md) و[دليل الصيانة](../docs/MAINTENANCE.md).
