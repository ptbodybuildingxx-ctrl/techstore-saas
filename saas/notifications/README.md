# SaaS external notification dispatcher
Deploy `index.ts` and `dispatch.mjs` together as a separate Supabase Edge Function in the dedicated SaaS project only. Never deploy to the original TechStore. Apply 056–057 first. Configure secrets in the server environment: SAAS_NOTIFICATION_WORKER_TOKEN (random 64 lowercase hex), SAAS_NOTIFICATION_ORIGIN (verified HTTPS platform origin), SAAS_EMAIL_ENABLED, SAAS_RESEND_KEY, SAAS_EMAIL_FROM (verified sender), SAAS_PUSH_ENABLED, SAAS_VAPID_PUBLIC, SAAS_VAPID_PRIVATE. Default channel flags are disabled. Set gateway JWT verification appropriately for a private worker call; the handler always checks its independent worker token. Schedule POST with x-worker-token and channel=email or push only after provider approval, and test with a consenting test account. Set only the public VAPID key as configuration.pushPublicKey in the frontend, never its private key. Shop path scopes are isolated; custom domains do not support Push yet. No external sender or scheduler is configured by this commit. Provider acceptance is not proof of receipt. Retries may duplicate push alerts; email uses provider idempotency, which is time-limited. Opt-out cancels pending work, but an already in-flight request cannot be recalled. Do not log recipient addresses or subscription keys.
