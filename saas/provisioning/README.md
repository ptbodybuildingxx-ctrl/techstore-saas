# Store provisioning preparation — no cloud execution
This offline tool stages the pinned 56 migrations, 3 Edge sources and per-store UI after checking a privately supplied inventory and new-target observations. It is NOT a trusted cloud worker: target observations must be obtained by an authorized operator from the provider immediately before actual use. Never use the example values against live resources. It makes no network calls, does not create projects, deploy, or mark a store ready. The generated receipt is a local integrity record, not proof of deployment or authorization.
Run Node 24:
```sh
node saas/provision-store.mjs inspect
node saas/provision-store.mjs prepare /private/request.json /private/new-output
```
Use the shape of request.example.json. Include every known existing project in existingProjects, explicitly classify every project other than the new target as protected or assigned, and include every assigned shop origin. The new target must be newly created, healthy and empty; confirm zero custom public tables, auth users, storage objects/buckets, edge functions and applied migrations. Never use a real service key in the browser or request. Each store uses an independent HTTPS origin. The existing 56 migrations and 3 functions are pinned by Git blob identity and packaged with SHA-256 digests; changed files require review and repinning. Static marker checks are NOT proof of clean install or complete security.
Before real deployment: obtain explicit cost approval and new project ref; check organization capacity; verify isolated destination with live inventory, migrate sequentially under trusted operator supervision, stop on any error, verify all grants/RLS and Edge secrets/redirects, create a unique owner through Auth, test full operations and backups on two test stores, and only then register a verified project identity. Never apply migrations to an existing project. No live payment or entitlement activation is authorized.

All three commercial Edge sources now require TECHSTORE_STORE_ORIGIN (the exact dedicated HTTPS origin) and TECHSTORE_PUBLISHABLE_KEY (the new project's publishable key) from environment variables; service credentials remain server-side. Do not use the original site's key or origin. Optional AI and push functionality remain subject to their own configuration and live tests. The commercial Edge changes have not been deployed.
