# Custom-domain activation (development only)
The central admin registers one current hostname per store, with a unique DNS TXT proof. Disabled names remain reserved until an authorized migration handles reassignment. The public resolver returns a slug only for active domains and a live storefront. Browser roles cannot activate domains. Do not enable `configuration.customDomainRouting` until dedicated HTTPS hosting serves only the storefront application on the custom host and trusted verification is deployed. The trusted backend must independently confirm the exact DNS TXT challenge and provider mapping to the intended tenant, check certificate/HTTPS and serve a tenant-specific challenge, and record hashed evidence before invoking mt_service_domain_activate. A hash is not proof by itself. Re-check ownership, routing and certificate periodically; disable on mismatch. Never use github.io, existing TechStore origins, shared admin origins, or arbitrary redirects. No real domain, DNS change, certificate, server, or activation is created here.
