# Super Admin development
Dedicated control plane only. This UI uses the actual control-plane URL and its **publishable** browser key; no service credentials. Run from a trusted local checkout with `python3 -m http.server 8765 --bind 127.0.0.1` and open `http://127.0.0.1:8765/saas/admin/`. Use a dedicated HTTPS origin before hosting. The shop UI is unchanged.
The database migration `../control-plane/admin-development.sql` must be installed after the base control-plane schema. It adds operator-only overview, registration and trial/suspend/cancel/reopen RPCs, plus private audit records. A registration has no project or origin and cannot be marked ready by these APIs. Trial is administrative metadata, not payment or store entitlement.
Create the operator in the dedicated project's Authentication > Users dashboard, verify ownership and email, then add the exact user UUID to saas_private.operators as an administrator. MFA remains required by default. A development-only exception may be assigned explicitly to one verified operator by setting mfa_required=false; re-enable it and configure MFA before commercial use. Never grant the role by public signup or user metadata. No real operator is included.
The UI uses a password login and an in-memory session; no persistent credentials or refresh token. It requires a fresh login after expiry. No hosting or MFA enrollment is implemented. The development UI is not authorized for commercial deployment. Payment, tenant projects, real license enforcement, backups and restoration require separate work. 
Run `npm run verify` in Node 24. The branch includes the previously tested catalog-isolation fix; no merge or publication is authorized by this development stage.
